# v1.2.0 开发日志

> 发布日期：2026-07-11

## 主题：移除 auto-apply（Phase 2），CLI 收敛为读侧 + 全量适配器审计

### 1. auto-apply 功能面移除（Breaking）

**删除文件：** `cli/src/apply.ts`（1830 行）、`cli/src/cdp.ts`、`cli/src/tencent-structured-fill.ts`、`cli/src/coverage.ts`（ENDPOINT_VERIFIED 静态表）、`cli/test/apply-smoke.ts`、`cli/test/debug-submit-smoke.ts`、仓库根 `extension/`（MV3 session 抓取扩展）。

**接口收缩：** `CompanyAdapter` 删除 `fetchApplicationSchema?`；全部 adapter 与工厂（moka/feishu/greenhouse/lever/liepin/wecruit/bespoke）剥离 apply schema 构造、`submit_kind`/`endpoint_verified`/`submit_notes` 字段与 `./apply.js`、`./cdp.js` 的 import。

**index.ts：** 删除 `apply`（per-company）、`profile`、`extension`、`recon` 四个 verb；`find` 删除 `--apply-ready` 与投递就绪图标分类；`list` 不再输出 `submit_kind`/`endpoint_verified`。

**保留的边界：**
- `memory event applied`（用户手记投递历史）保留。
- `match`/`resume-check` 省略 `--resume` 时回落 `~/.jobpro/profile.json` 的 `resume_path` 行为保留（只删 `profile` 命令面，不删读取回落）。
- `status` 精简为 profile（exists + resume_path）+ memory。
- `selftest` 重写为读侧三步：xpeng search → detail → 内联简历 match（离线）。

**理由：** 42/50 家投递需要 <30 天有效期的浏览器 session + 各家私有提交格式，维护成本与实际可用率不成比例；砍掉半吊子功能，读侧质量优先。代码在 git 历史里，Phase 2 重启时可考古。

### 2. 全量适配器读侧审计（承接 v1.1.15 moka 方法论）

对其余 43 家（moka 7 家已在 v1.1.15 修复）按统一标准真实 API 实测：

- 关键词搜索不漏岗（对照官网交叉验证可疑的 0 结果）
- `all` 无重复 post_id、total 与实际一致
- `detail` 返回非空 JD 或明确 not-supported
- scope 报错干净（supportedScopes 提示而非静默 0）

审计结论：43 家中 8 健康 / 6 存疑 / 29 broken。以下按 bug 类别记录修复（每项均先用 curl/SPA bundle 实测确认根因、修后用真实 API 复验）：

### 分页参数错误（重复+漏岗同根因）

- **baidu**：`pageNum` → `curPage`（上游静默忽略未知参数永远回第 1 页）；pageSize 上游上限 20，超限 clamp。
- **netease**：`pageNum` → `currentPage`；旧注释「pageNum 需登录才生效」实为参数名错误。修后 all 可穷尽 total（原 200 封顶）。
- **pingan**：`pageNo` → `pageNum`；all 加去重+停滞保护。
- **xiaohongshu**：翻页 `page` → `pageNum`、搜索 `keyword` → `positionName`（服务端过滤，实测 前端→23 条全相关）；修前 85% 岗位不可达、all 返回 350 行 300 重复。
- **jd**：上游 pageIndex 是 0-based，CLI 1-based 直传导致每个 bucket 首页永远丢失（present bucket「total>0 但 items 恒空」正是此因）；改传 page-1。
- **byd**：上游把 pageNum 当**行偏移**：改传 (page-1)*pageSize；all 去重（含上游自身重复行）。
- **agibot**：上游只认 `limit`+`offset`（page_index/page_size 全被忽略）；campus 无渠道 → 收窄 supportedScopes 干净报错。
- **antgroup**：pageSize=50 是上游边界坏值（49 可用、50 返回 success:false）：clamp 到 49；maxPages 提升穷尽 1463 岗。

### 搜索关键词失效

- **oppo**：`keyword` → `positionName`（实测 工程师→74/算法→35，旧字段恒 123 全量）；博士生项目归入 campus scope。
- **kuaishou**：上游服务端过滤字段是 `name`（audit 前注释错称无服务端搜索）；避开 pageNum=1+pageSize=10 的上游毒缓存组合。
- **trip**：上游 getJobAd 忽略 searchText/pageIndex/pageSize（全模式单次全量返回）：重写为全量拉取+客户端过滤/切页；默认 scope 改 social（campus 上游为空导致误导 0）；detail 直接用列表行自带 JD，全渠道扫描。

### 数据源迁移 / 漏渠道（漏岗大头）

- **sensetime**：北森 Wecruit → 飞书招聘自定义域（见前节）。
- **vivo**：数据源整体指错——旧 adapter 接的 vivo.zhiye.com 是「员工招聘」边缘门户（36 个操作岗）；重写为 hr.vivo.com 官方社招 SPA API（`POST /api/social/webSite/portal/page`，从 SPA chunk 反解）+ hr-campus.vivo.com 校招；detail 校验返回 id 与请求一致（旧实现任意 id 都返回第一条的 JD）。
- **xpeng**：旧 adapter 只接了美国 Greenhouse board（19 岗）；重建在 feishu 工厂上（xiaopeng.jobs.feishu.cn，社招 index 1551 岗 + 校招渠道）。
- **weride**：探测笔记用错 slug 漏掉整个中国区——Moka 租户是原名景驰 `jingchi`（社招 siteId 2138 + 校招 2137）；重写为 Moka 主源 + Lever 合并的双源 adapter。
- **hoyoverse**：Greenhouse board 已弃用清空（HTTP 200 空列表，故 CLI 无从报错）；重写为 SmartRecruiters 公开 API（api.smartrecruiters.com/v1/companies/HoYoverse）。
- **alibaba**：硬编码单 batchId 漏 3 个在招 batch 共 646 岗；新增 listBatch 动态发现全部 batch 循环合并，campus scope 映射 graduate batch（阿里星）。
- **minimax**：社招挂在同租户 `index` 门户：config 加 `socialChannel: "index"`，all 从 77 → 267 全可达。
- **nio**：社招渠道（根路径，2428 岗）已开通：config 加 `socialChannel: ""` 恢复 social scope。
- **iflytek**：Beisen Category 字典是 per-tenant 的，旧映射照抄 vivo 租户；实测本租户字典重建映射（社招=1 共 695 岗，旧映射把 8 个飞星计划岗当社招）。
- **lilith**：57/110 漏岗根因不是滚动抓取不全——`index` 渠道本身是策展子门户；直连 HTTP（学 sensetime 空 channel 模式）拿全量 110 岗，同时修掉进程挂起（浏览器句柄未释放）。
