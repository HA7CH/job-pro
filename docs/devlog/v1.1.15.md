# v1.1.15 开发日志

> 发布日期：2026-07-11

## 修复内容 / 新增功能

影响所有 moka 工厂租户（7 家）：cambricon / deepseek / galaxyuniversal / geely / moonshot / megvii / stepfun。

### 1. moka 搜索改为服务端 keyword 匹配（修复漏岗）

**文件：** `cli/src/moka.ts`（`searchOneChannel` / `fetchEncryptedPage`）

**根因：** 两个叠加的问题。
1. `searchOneChannel` 只对 SSR init-data 里的岗位做客户端关键词过滤，而 init-data 只埋了岗位板的一个前缀（实测 high-flyer 埋 15 / 36）。不在前缀里的岗位（如 DeepSeek「前端 / 客户端开发工程师」）永远搜不到，却返回 `ok: true, total: 36, positions: []`，极易被误读为「没有岗位」。
2. `fetchEncryptedPage` 发给 `jobs/v2` 的分页参数名是错的：上游接受的是 `limit` / `offset`（从 SPA bundle `recruitmentWeb-20260706-*.js` 反解并实测验证），`pageNum` / `pageSize` 被静默忽略，服务端永远按默认 `limit=10, offset=0` 返回同一页。

**修复：**
- `fetchEncryptedPage` 请求体改为 `{ orgId, siteId, limit, offset: (pageNum-1)*limit, needStat, locale: "zh-CN", keyword? }`。上游 `limit` 上限 50（100 返回 code 102 参数错误），新增 `clampPageSize` 统一钳制。
- `searchOneChannel` 在拿到 aesIv 后优先走加密接口做服务端搜索（keyword 由上游全量匹配；带 keyword 时 `jobStats.total` 即过滤后总数，直接透传）；加密接口失败时第一页降级回 init-data 客户端过滤，`page > 1` 则如实报 `pagination failed`。

### 2. `fetchAllPositions` 去重 + 真实翻页（修复 45 = 15×3 重复）

**文件：** `cli/src/moka.ts`（`fetchAllOneChannel`）

**根因：** 同上——翻页参数被上游忽略，每页返回相同内容，旧循环直接 `push(...more.jobs)` 且以 `collected.length < total` 为继续条件，收敛前会把同一批岗位叠加多次（实测 `deepseek all` 返回 45 条 = 15 唯一 × 3）。

**修复：** 从 offset 0 开始扫加密接口（keyword 一并下推），按 `id` 去重；单页新增数为 0（防御上游再次忽略 offset）、收满 `total`、或返回短页时停。首页即失败时降级为 init-data 前缀过滤。

### 3. `fetchPositionDetail` 落地实现（原为「not implemented」占位）

**文件：** `cli/src/moka.ts`（`fetchPositionDetail`、新增 `DETAIL_ENDPOINT` / `htmlToText`）

**根因：** 旧实现直接返回 `ok: false`「需要 encrypted-session flow」。实际上 SPA 的单岗接口 `POST /api/outer/ats-apply/website/job`（body `{orgId, siteId, jobId, locale}`）匿名可用，返回与 `jobs/v2` 相同的 AES 信封，解出的岗位对象带完整 `jobDescription`（HTML）。

**修复：** 复用 portal 抓取（拿 aesIv + locale cookies）→ POST 单岗接口 → `decryptMokaEnvelope` 解密 → 返回 feishu 工厂同款 detail 形状 `{ok, source, post_id, title, project, recruit_label, bgs, work_cities, description, apply_url}`。`jobDescription` 经新增的 `htmlToText` 压平为可读纯文本。岗位不存在时透传上游文案（「您访问的职位已不存在…」）。顺带 `fetchApplicationSchema` 的 `job_title` 现在能取到真实标题。

### 4. review 轮补修（对抗性审查发现）

**文件：** `cli/src/moka.ts`

- **detail 跨通道重试**：上游 jobId 与 siteId 强绑定（用错通道的 siteId 查返回 703015「职位已不存在」，megvii 实测）。双通道租户（megvii campus+social、cambricon）下旧实现只查 `defaultChannel()`，另一通道的岗位全部误报不存在。现按默认通道优先逐通道重试，成功通道决定 `apply_url`（deeplink 因此也指向正确 portal）。
- **`work_cities` 回归修复**：megvii 的 jobs/v2 行完全不带 `locations`（SSR 同岗有）。搜索改用加密数据源后城市字段会退化为空串，新增 `enrichFromSsr` 按 id 把 SSR 的 locations 嫁接回来。
- **total 兜底死代码**：`fetchEncryptedPage` 原 `jobStats?.total ?? 0` 使调用方的 `enc.total ?? total` 永远不触发；某页缺 `jobStats` 时 `all` 扫描会被 `collected.length >= 0` 提前截断。改为透传 `undefined`。
- `htmlDecode` 的 `&amp;` 改到最后解（双重转义不再误解）；`htmlToText` 换行标签补 `td|th`。

### 5. 附带小修

- `MokaJob` 补 `jobDescription?` 与 `locations[].cityName?` 类型；`workCitiesFor` 增加 `cityName` 兜底（detail 接口的 locations 带 `cityName`，portal 的 `jobsGroupedByLocation` 可能没有对应区级 id，如 DeepSeek 前端岗的「拱墅区 / 海淀区」）。
- 文件头协议注释重写，记录 limit/offset/keyword 语义与单岗接口，附探测日期。
