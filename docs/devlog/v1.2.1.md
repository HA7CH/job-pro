# v1.2.1 开发日志

> 发布日期：2026-07-14

## 修复内容

### MiniMax 社招岗位详情链接按门户渠道生成

**文件：** `cli/src/feishu.ts`、`cli/src/minimax.ts`、`cli/test/unit-smoke.ts`

**根因：** MiniMax 的飞书招聘租户同时使用 `379481` 校招门户和 `index` 社招门户。v1.2.0 已让搜索请求按 scope 切换 `portal-channel`，但 `summarizePosition` 仍始终使用单一的 `applyUrlPrefix`。因此从 `index` 搜到的社招岗位被错误链接到 `/379481/position/<id>/detail`。错误门户仍返回 HTTP 200，但前端渲染“该职位已下线”，所以常规状态码检查无法发现问题。

**修复：** `FeishuAdapterConfig` 新增可选的 `applyUrlPrefixByChannel`。搜索结果将实际请求渠道传给 `summarizePosition`，跨渠道详情扫描也将命中渠道传入 URL 生成逻辑。MiniMax 为 `index` 配置社招详情前缀，默认前缀继续服务 `379481` 校招/实习门户。

**测试：** 单元 smoke 使用本地模拟响应验证社招搜索生成 `/index/` 链接、校招搜索保留 `/379481/` 链接；真实 CLI 验证会检查 MiniMax FDE 社招搜索与详情输出。

## 已知问题

飞书招聘的错误门户可能以 HTTP 200 返回“职位已下线”页面，后续审计其他多门户租户时应校验渲染内容或使用明确的 per-channel URL 配置，不能只依赖 HTTP 状态码。
